**Findings**
1. **Temporary DAP ownership conflicts with a concurrently starting LSP owner** (`SPEC.md:41`, `SPEC.md:149-164`, `SPEC.md:202-206`). If DAP acquires the project lock first, LSP reports “another Zed window”; when DAP exits it kills Godot, leaving no language server. **Fix:** require an existing LSP owner in phase 2, or define a real ownership-transfer protocol. The minimal safe design is for DAP to wait briefly for the LSP owner and fail clearly if none exists. Do not create temporary owners without specifying promotion to LSP ownership.

2. **DAP discovery races against owner startup and cleanup** (`SPEC.md:142-147`, `SPEC.md:202-209`). “If an owner is alive, read its state” treats PID/state as synchronization. DAP can observe a held lock before state exists, incomplete startup, stale state after owner death, or state replacement. **Fix:** make the owner socket authoritative. DAP should resolve the project, connect/query the socket for a versioned `{status, project, dap_port, owner identity}` response, and wait while the lock is held but the socket is not ready. Only acquire the project lock after proving no owner holds it.

3. **Stale-editor adoption contradicts process ownership** (`SPEC.md:153-154`, `SPEC.md:191-197`). `PR_SET_PDEATHSIG` should terminate Godot when its owner dies. If it survives, the new bridge is not its parent and cannot satisfy the promised `waitpid`; state also omits the recorded PGID. **Fix:** remove adoption. After acquiring the lock, validate stale identity, terminate the stale verified process group if necessary, wait for disappearance, then spawn a new child. Add `godot_pgid` to state. Handle the PDEATHSIG parent-death race by setting it and then verifying the captured parent PID in `pre_exec`.

4. **DAP settings resolution is inconsistent with Zed settings** (`SPEC.md:90-106`, `SPEC.md:165-168`, `SPEC.md:202-206`). Reading only `<worktree>/.zed/settings.json` loses merged user settings and may fail on Zed’s JSON-with-comments format. It also ignores the unmanaged `lsp_port` branch and may spawn a second editor. **Fix:** in `get_dap_binary`, use `LspSettings::for_worktree("godot", worktree)` and pass the resulting settings to `godot-bridge dap` through a defined argument or environment value. DAP must connect directly to `dap_port` when `lsp_port` is configured and never consult managed ownership state.

5. **The Zed DAP return contract is incomplete** (`SPEC.md:328-332`). `DebugAdapterBinary` requires `request_args`; `get_dap_binary` receives adapter configuration as JSON in `DebugTaskDefinition.config`, not a dedicated `file` parameter. The spec only defines command construction. **Fix:** specify that `get_dap_binary` parses `config.config`, derives optional `file`, and returns `request_args.configuration` containing the adapter configuration plus `request_args.request` from `request`. Preserve the Task 0 substitution check because substitution timing determines whether `file` is usable for process arguments.

6. **Port allocation and readiness remain racy** (`SPEC.md:155-161`). The project lock does not prevent another project or process taking a bind-and-close port. Parsing output for a bind-error string and retrying once is brittle. Disposable DAP readiness connections can also be consumed as real DAP clients. **Fix:** retry allocation/spawn until the shared deadline, based on child exit and inability to establish the retained endpoint, not log text. Connect once and retain the LSP socket. Do not probe DAP during phase 1; the DAP proxy should establish and retain its own connection when needed.

7. **The worktree root used for root resolution is not defined early enough** (`SPEC.md:104-120`). `project_dir` is evaluated before `rootUri`, but a relative `project_dir` needs the worktree root. `rootUri` versus `workspaceFolders` precedence and non-file URI handling also remain ambiguous. **Fix:** first derive the worktree root from the first valid `file:` workspace folder, otherwise `rootUri`; URL-decode and canonicalize it. Then apply `project_dir`, direct-project, and scan rules. Reject non-file URIs and define behavior when workspace folders identify different roots.

8. **`extra_args` can invalidate managed invariants** (`SPEC.md:102`, `SPEC.md:155-160`). Appending arguments allows duplicate `--path`, `--lsp-port`, `--dap-port`, `--editor`, or `--headless`, making state and readiness checks point at the wrong process. **Fix:** reject bridge-owned flags in `extra_args`, or place user arguments first and append authoritative managed flags last. Explicit rejection gives clearer behavior.

9. **The owner socket has no implementable protocol** (`SPEC.md:146-147`, `SPEC.md:202-209`). Creation timing, framing, commands, responses, timeouts, stale socket removal, identity validation, and concurrent clients are unspecified. **Fix:** define a small newline-delimited JSON protocol now, including `version`, `status`, and `project`; bind only after lock acquisition, remove a stale socket while holding the lock, publish `starting` then `ready`, validate the canonical project, and remove it before releasing the lock.

10. **Normal and abnormal proxy termination are conflated** (`SPEC.md:172-187`, `SPEC.md:219-220`). Phase 1 says malformed Godot framing is a crash, but does not define the response to pending requests, exit status, or behavior for an unexpected TCP EOF. DAP-generated `terminated`/`exited` events also need valid monotonically increasing `seq` values and bounded pre-connect buffering. **Fix:** define phase-1 unexpected Godot EOF/framing failure as fatal: close Zed output, clean up, and exit nonzero. For DAP, cap buffered bytes/messages, track the highest server sequence, synthesize unique sequence numbers, and distinguish client EOF/disconnect from editor death.

11. **Logging requirements conflict operationally** (`SPEC.md:192-194`). A child writing directly to a file cannot be capped by rename rotation: it continues writing to the old inode. Truncating on every spawn also defeats spawn-time rotation. **Fix:** either remove the 20 MiB cap for phases 1/2, or pipe stdout/stderr through a bridge-owned writer that performs bounded rotation and maintains the startup tail.

12. **Concurrent DAP sessions are unspecified** (`SPEC.md:39-41`, `SPEC.md:202-220`). Godot accepts multiple DAP clients, but launch, breakpoints, and the default debugger state are shared; two Zed sessions can interfere. **Fix:** add a separate per-project DAP-session lock and reject a second session for phases 1/2, unless multi-session behavior is explicitly tested and supported.

**Recommended Approach**
Use one strict LSP owner as the only managed-editor lifecycle authority through phase 2. Make the flock establish ownership, the Unix socket establish readiness, and the state file informational only. This avoids process-parent transfer, stale-state arbitration, and DAP/LSP promotion.

Trade-off: requiring LSP before DAP weakens standalone debugging, but it is substantially smaller and race-free. Supporting standalone DAP requires a persistent guardian or explicit ownership-transfer design, neither currently specified.
